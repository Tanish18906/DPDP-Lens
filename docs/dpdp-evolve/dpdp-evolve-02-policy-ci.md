## Tasks
1. policy.py and engine/dpdp_lens/policies/default.yaml. Pydantic models, YAML via the existing pyyaml. Fields: policy_id, version (semver string), effective_date, description, source, rules: one per check id with `action: block|warn|info` and optional `severity_override`. Clauses are NOT copied: they stay in clauses.json, the policy references check ids. Defaults: critical and high block, medium warn, low info. Every check id in the registry must have a rule (test fails otherwise). Add contract/policy.schema.json generated from the model. A policy file with an unknown check id, bad action or bad version is an error, never silently ignored.
2. Evaluator (pure, deterministic): `evaluate(scan, policy, project_cfg, suppressed_fps, baseline_fps, new_only) -> Evaluation` with decision pass|warn|fail|incomplete and items [{fingerprint, check, severity, action, is_new, suppressed}]. Rules: incomplete scan (scan.complete False) gives decision "incomplete" always. fail if any non-suppressed item with action block (and is_new when new_only). warn if any warn items. pass otherwise. Records policy_id, version and a sha256 of the policy file.
3. Project config `.dpdp-lens.yml` in the scanned repo: `policy` (path or "default"), `block_on` and `warn_on` (severity lists, override the policy actions), `categories` (layers to include, default code, config, frontend), `new_only` (bool), `baseline` (path, default .dpdp-baseline.json), `suppress` (list of {fingerprint, reason, by}). Validate it. Missing file means defaults.
4. CLI: `python -m dpdp_lens ci --repo-dir . [--config FILE] [--baseline FILE] [--new-only] [--write-baseline] [--sarif FILE] [--json FILE] [--summary FILE]`. Static mode by default (no running app needed). Exit codes: 0 pass or warn, 1 fail (blocking findings), 2 incomplete scan, invalid config or invalid policy. Never exit 0 when the scan is incomplete. `--write-baseline` writes {"version":1,"policy":..., "fingerprints":[{"fp","check","title","file"}]}. `--summary` writes Markdown for $GITHUB_STEP_SUMMARY: decision at the top, counts, new blocking findings table (id, check, file:line, clause), "N existing findings in baseline", coverage line "static checks only, n of 19", footer "Readiness report, not a compliance certificate".
5. sarif.py (only you edit it): physicalLocation only with a repo-relative file URI, never a URL. Findings without a file (live api or db findings) are left out of SARIF and stay in the JSON. Add `partialFingerprints: {"dpdpLens/v1": fingerprint}`, ruleId, level, help text with clauses. Test: validate the output against the official SARIF 2.1.0 JSON schema vendored under engine/tests/fixtures/ (record its source and licence in README credits). Keep the existing sarif tests green or update them deliberately.
6. Workflow `.github/workflows/dpdp-lens.yml` (also provide a copy for the demo repo under docs/ci-example/): triggers pull_request, push to main, schedule (cron every 6 hours), workflow_dispatch. Steps: checkout, setup-python 3.12, `pip install "git+https://github.com/Tanish18906/dpdp-lens#subdirectory=engine"` (pin to a commit sha for the demo), run `ci` with --sarif, --summary >> $GITHUB_STEP_SUMMARY, upload-sarif (if: always() and repo is public), upload-artifact for json and sarif, optional Slack incoming webhook post from secret SLACK_WEBHOOK_URL when decision is not pass. Permissions: contents read, security-events write. It must not require any change to the scanned app's source.
7. Tests: decision matrix (pass, warn, fail, incomplete), new_only with a baseline, suppression, invalid policy exits 2, forced scanner failure exits 2 and never 0, summary markdown snapshot, SARIF schema validation, `ci` on clean_app exits 0, on target-app exits 1 with block rules. Add scripts/gates/gate_ci.sh: runs ci against target-app with a baseline of all current findings (exit 0), then against a temp copy with one added `logger.info("x %s", req.aadhaar)` line (exit 1, exactly one new finding).
