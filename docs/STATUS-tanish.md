- Fix endpoint rules (T10): POST /findings/{id}/fix?scan_id=...&mode=live|cached returns {finding, score_before, score_after, mode, fallback_reason}. Only infrastructure failures and the 60 second limit fall back to data/golden/V1.json (mode "cached_golden" plus a fallback_reason). A patch that does not apply (PatchError) is a 422 with no fallback. A live run that finishes but is not verified is returned as is (verified false, finding stays open, no fallback). Golden files are written only from a verified live run. Cached mode scores the actual stored scan.
- V5 fix (T12): a Template edit is (root, file, old, new) with root "backend" or "frontend". For a frontend template, Sandbox copies target-app/frontend (no node_modules, dist), symlinks the ORIGINAL node_modules into the copy, runs `vite build`, serves dist with `python -m http.server` and re-scans that URL. It needs `npm install` done once in target-app/frontend. Without node_modules the V5 fix raises (setup error), and the API falls back to data/golden/V5.json labelled cached_golden. A build failure is a PatchError (422). `tests_passed` for V5 means the backend pytest suite passed and the patched frontend built. verify_fix raises if the template's scanner (api_scan, log_scan, browser_scan) failed during the re-scan, so a scan that could not run never reads as "finding gone".
